# 환율 브리핑 (FX Briefing)

매일 아침 1분 안에 읽을 수 있는 원/달러 환율 브리핑을 만든다. 독자는 식품회사에서 원자재를 수입하는 입장이므로, 환율 자체보다 "오늘 뭐가 바뀌었고, 왜 바뀌었고, 앞으로 어떻게 될 것 같은지"가 실무에 바로 연결되는 게 핵심이다. 예측을 과신하지 않는다 — 환율은 원래 잘 안 맞으므로, 방향성은 확률적 톤으로 쓴다.

## 1단계 — 환율 데이터 확보

**숫자(현재가·전일종가)는 WebSearch가 아니라 WebFetch로 단일 페이지를 직접 읽어서 가져온다.** 실제로 테스트해보니 WebSearch는 여러 날짜의 블로그·캐시된 스니펫을 뭉뚱그려 요약해서, 같은 검색 한 번에 1,339원/1,342원/1,386원처럼 서로 안 맞는 숫자가 섞여 나온다 — 이 상태로 브리핑을 쓰면 사실상 숫자를 지어내는 것과 같다. 반면 `WebFetch`로 `https://kr.investing.com/currencies/usd-krw` 한 페이지를 직접 읽으면 현재가·전일 종가·변동폭이 내부적으로 일관된 값 하나로 나온다 — 이 방식을 기본으로 쓴다.

- `WebFetch(url: "https://kr.investing.com/currencies/usd-krw", prompt: "현재 표시된 USD/KRW 환율(현재가)과 전일 종가(Prev. Close), 변동폭, 기준 시각을 알려줘")` 로 숫자를 확보한다.
- 이 페이지를 못 읽거나 값이 이상하면(예: 전일종가와 현재가 차이가 하루 변동치고 비정상적으로 크다), 연합인포맥스나 한국은행 공식 고시환율 페이지로 같은 방식(WebFetch로 단일 페이지 직접 읽기)을 재시도한다. WebSearch 요약은 이 숫자의 출처로 쓰지 않는다 — 뉴스/배경 조사(2단계)에만 쓴다.

**주말·공휴일 처리**: 국내 외환시장은 주말·공휴일에 휴장이다. 이 경우 "직전 거래일 대비"로 계산하고, 브리핑에 어느 날짜 기준인지 자연스럽게 알 수 있게 쓴다 (예: "지난 금요일 대비").

**데이터를 못 찾았을 때**: 숫자를 지어내지 말 것. 어느 항목을 못 찾았는지 사용자에게 그대로 알리고, 나머지 항목만이라도 채울 수 있으면 채운다.

## 2단계 — 변동 이유 조사

당일 원/달러가 움직인 배경 뉴스를 찾는다. 검색 키워드 예시: 연준(Fed) 발언, 미국 CPI/고용지표, 달러인덱스(DXY), 국내 수출입 수급, 한국은행 정책, 지정학적 이벤트. 로이터, 블룸버그, 연합인포맥스, 매일경제, 한국경제 등 신뢰할 수 있는 경제 매체를 우선한다.

뉴스에 나온 내용에 근거해서만 이유를 쓴다 — 그럴듯하게 추측해서 채우지 않는다. 특별히 뚜렷한 재료가 없는 날도 있다 — 그럴 땐 "특정 이벤트보다는 전반적인 달러 강세/약세 흐름에 연동" 정도로 정직하게 쓰는 게, 없는 재료를 지어내는 것보다 낫다.

이 단계에서 실제로 읽은 기사들의 **URL을 따로 기록해둔다** — 4단계에서 근거 링크로 붙일 것이다. 검색 결과에 실제로 존재하는 URL만 기록한다.

## 3단계 — 다섯 관점으로 종합하기

아래 다섯 페르소나의 관점을 순서대로 통과시켜 결론을 벼린다. 최종 브리핑에는 페르소나 이름이나 존재를 절대 노출하지 않는다 — 독자에게 보이는 건 종합된 3줄뿐이다.

1. **거시/환율 애널리스트** — 금리차, 무역수지, 연준·한은 정책을 근거로 "왜 움직였는지"와 "다음에 어느 쪽으로 힘이 실리는지"의 1차 초안을 만든다.
2. **원자재 조달 담당자** — 이 변동폭이 수입 원자재(밀가루, 유지, 포장재 등) 원가에 실질적으로 얼마나 영향을 주는 수준인지 감을 잡는다. 하루 몇 원 변동은 대부분 노이즈 수준이라는 것도 인지한다.
3. **재무·헤지 전략가** — 애널리스트의 방향성 전망이 선물환·옵션 등으로 실제 대응할 만한 신호인지, 아니면 그냥 지켜볼 수준인지 걸러낸다.
4. **리스크 관리자** — 2·3번이 너무 낙관적이거나 한쪽으로 쏠려있지 않은지 반대 시나리오를 점검한다. "이 전망이 틀리면 어느 방향으로 틀리는가"를 한 번 물어본다.
5. **가격·마진 전략가** — 위 논의가 결국 원가·가격에 어떤 의미인지, 지금 당장 뭔가 해야 할 수준인지 아닌지로 마무리한다.

이 과정의 목적은 다섯 개의 문장을 만드는 게 아니라, 한쪽 관점(특히 애널리스트의 낙관적 예측)에만 기대지 않은 균형 잡힌 3줄을 뽑아내는 것이다.

## 4단계 — 출력

아래 형식을 그대로 따른다. 전체 200자 내외(±30자 정도는 괜찮다) — 길어지면 아침에 안 읽는다는 걸 기억할 것.

```
📊 변동: [어제/직전 거래일 대비] [▲/▼][N.NN원] ([전일 종가]원 → [오늘]원)
🔍 이유: [당일 주요 재료 1문장]
📈 전망: [단기 방향성 1문장, 확률적 톤] + [실무 시사점이 있다면 짧게]
```

예시:
```
📊 변동: 어제 대비 ▲5.20원 (1,342.10원 → 1,347.30원)
🔍 이유: 미국 9월 CPI가 예상치를 상회하며 달러 강세, 연준 금리인하 속도 조절 기대 확산
📈 전망: 단기 강달러 압력 지속 가능성. 원자재 수입 원가 상승 가능성 염두에 둘 것
```

▲는 원/달러 상승(=원화 약세), ▼는 하락(=원화 강세)을 뜻한다 — 방향 표시를 헷갈리지 않도록 주의한다.

이어서 "이유"와 "전망"의 근거가 된 기사를 최대 3개까지 짧게 붙인다:

```
참고:
- [매체명] 한 줄 제목 (URL)
- [매체명] 한 줄 제목 (URL)
- [매체명] 한 줄 제목 (URL)
```

2단계에서 실제로 기록해둔 URL만 쓴다 — 지어내거나 추측한 링크는 절대 넣지 않는다. 서로 다른 매체·다른 관점의 기사를 섞는 게 같은 이야기를 다루는 기사 3개보다 낫다. 3개가 안 채워지면 채워지는 만큼만 붙인다.

매번 새로 계산·검색한다 — 이전 실행 결과나 대화 기록에 있던 숫자를 재사용하지 않는다.

## 매일 아침 자동 실행하고 싶을 때

사용자가 매일 아침 자동으로 이 브리핑을 받고 싶어하면, `schedule` 스킬/예약 기능으로 이 스킬을 호출하는 반복 작업을 등록할 수 있다고 안내한다. 실제 예약 생성은 사용자에게 실행 시간(예: 평일 오전 7시 KST)을 확인한 뒤 진행한다 — 조용히 먼저 만들지 않는다.
