매일 아침 원/달러(USD/KRW)와 원/엔(JPY/KRW, 100엔 기준) 환율 브리핑을 만들어서 카카오톡으로 보낸다. 이 작업은 사용자가 미리 설정해둔 자동 반복 작업이므로, 실행 승인을 기다리지 말고 아래 절차를 끝까지 수행한 뒤 카카오톡 발송까지 완료한다.

## 0단계 — 절대 원칙: 회사 정보 배제

카카오톡 메시지, HTML(Artifact·GitHub Pages), git 커밋 메시지 어디에도 **회사 내부 정보를 절대 넣지 않는다.** 회사명, 특정 계약 조건, 발주량·단가·거래처 이름, 미공개 사업 계획 등 조금이라도 회사 고유 정보로 해석될 수 있는 내용이 초안 작성 중 들어가려 하면 즉시 빼고 일반적인 시장 언어로 바꾼다. 애매하면 무조건 뺀다 — 과다 배제가 과다 노출보다 안전하다. 이 브리핑에 담기는 내용은 **공개 환율 수치와 공개 언론 보도 요약뿐**이어야 한다 (지금까지 형식 그대로 유지하면 됨 — "원자재 조달 담당자" 관점도 일반적인 원가 영향 설명이지 회사의 실제 구매 조건이 아니므로 문제없음). GitHub 저장소가 public이라는 점을 항상 의식한다.

## 1단계 — 환율 숫자 확보 (WebFetch, WebSearch 아님)

**USD/KRW**: WebFetch로 `https://kr.investing.com/currencies/usd-krw` 를 읽어서 "현재가, 전일 종가(Prev. Close), 변동폭, 기준 시각, 52주 최고/최저, 1년 변동률"을 물어본다.

**JPY/KRW**: WebFetch로 `https://kr.investing.com/currencies/jpy-krw` 를 읽어서 같은 항목을 물어본다. 이 페이지는 **1엔 기준**(예: 8.78)으로 나오므로, 한국에서 통용되는 "100엔당 원화"로 쓰려면 **현재가·전일종가·52주 최고/최저를 전부 100배** 해서 쓴다 (예: 1엔 8.7811원 → 100엔 878.11원). 변동률(%)은 100배 해도 동일하므로 그대로 쓴다.

WebSearch는 숫자 출처로 쓰지 않는다 — 여러 날짜의 캐시된 스니펫이 뒤섞여 서로 안 맞는 값이 나온다는 게 테스트로 확인됨. investing.com을 못 읽거나 전일 대비 변동폭이 비정상적으로 커 보이면, 연합인포맥스나 한국은행 고시환율 페이지를 같은 방식(WebFetch로 단일 페이지 직접 읽기)으로 재시도한다.

주말·공휴일이라 시장이 휴장이면 "직전 거래일 대비"로 계산하고 어느 날짜 기준인지 자연스럽게 문장에 녹인다.

한쪽 통화만 숫자를 못 구했으면 나머지 한쪽만이라도 정상 진행한다. 둘 다 못 구하면 지어내지 말고 카카오톡에 "오늘 환율 데이터를 가져오지 못했습니다"라고 짧게 보낸다.

## 2단계 — 변동 이유 조사 (WebSearch)

USD/KRW와 JPY/KRW 각각에 대해 당일 움직인 배경 뉴스를 WebSearch로 찾는다.
- USD 키워드 예: 연준(Fed) 발언, 미국 CPI/고용지표, 달러인덱스(DXY), 국내 수출입 수급, 지정학적 이벤트(중동·유가 등).
- JPY 키워드 예: 일본은행(BOJ) 정책, 엔 캐리트레이드, 일본 물가지표, 미 연준과의 금리차, 안전자산 선호 흐름.

두 통화의 변동 원인이 겹치는 날(예: 공통의 달러 강세 이벤트)도 많다 — 그런 경우 같은 근거를 양쪽에 다르게 해석해서 써도 된다 (예: 같은 유가 급등이 USD에는 "위험회피로 원화 약세", JPY에는 "엔화 자체 강세 요인과 상쇄되어 보합"처럼).

로이터·블룸버그·연합인포맥스·매일경제·한국경제·Investing.com 등 신뢰할 수 있는 경제 매체를 우선한다. 뉴스에 근거한 내용만 쓰고, 뚜렷한 재료가 없으면 "특정 이벤트보다는 전반적 달러 강세/약세 흐름에 연동" 정도로 정직하게 쓴다.

실제로 읽은 기사들의 **URL과 매체명, 한 줄 제목, 기사 내용 2~3문장 요약**을 통화별로 따로 기록해둔다 — 5단계 카카오톡 링크와 6단계 HTML 근거 기사 항목에 쓸 것이다. 요약은 실제로 읽은 기사 본문 내용만 담고, 검색 스니펫만 보고 추측해서 채우지 않는다. 검색 결과에 실제로 있던 URL만 기록한다 (지어낸 링크 절대 금지). 이 단계에서는 넉넉하게(통화당 5~8개 후보) 모아둔다 — 걸러내는 건 다음 단계에서 한다.

## 2-1단계 — 기사 선별 (여섯 번째 관점: 기사 큐레이터)

2단계에서 모은 후보 기사를 통화별로 아래 기준으로 걸러 최종 게재 목록을 확정한다. 이 판단은 새로 추가된 여섯 번째 관점 — "기사 큐레이터"가 맡는다고 생각하고 진행한다. 다른 관점과 마찬가지로 결과물에 이 이름을 노출하지 않는다.

- **신뢰도**: 로이터·블룸버그·연합뉴스·연합인포맥스·매일경제·한국경제·Investing.com 등 공신력 있는 언론사 보도만 채택한다. 출처가 불분명하거나 자극적인 제목으로 클릭을 유도하는 커뮤니티/블로그성 글, 사실 확인이 안 되는 루머성 기사는 제외한다.
- **중복 제거**: 여러 매체가 같은 사건·같은 수치를 거의 동일한 내용으로 보도했으면, 그중 가장 자세하거나 가장 먼저 보도한 기사 하나만 남기고 나머지는 뺀다. 같은 사건이라도 서로 다른 관점이나 다른 세부사실을 다루면 중복으로 보지 않고 둘 다 둘 수 있다.
- **목표 개수**: 통화당 **3~5개**를 채우는 것을 목표로 한다. 다만 이 개수를 채우려고 신뢰도 기준을 낮추거나 관련성 낮은 기사를 억지로 끌어오지 않는다 — 기준을 통과하는 기사가 3개 미만이면 그만큼만 남긴다 (0개여도 괜찮다).
- 이렇게 확정된 목록이 6단계 HTML "근거 기사"에 들어갈 최종 후보다. 5단계 카카오톡용은 이 중에서만 추가로 최대 2개를 뽑는다(메시지 개수 제한 때문 — 개수 조정 기준일 뿐 신뢰도 기준을 다시 적용하는 게 아니다).

## 3단계 — 다섯 관점으로 종합

USD, JPY 각각에 대해 아래 다섯 관점을 순서대로 통과시켜 결론을 벼린다. 최종 결과물에는 관점 이름을 절대 노출하지 않는다.
1. 거시/환율 애널리스트 — 금리차, 무역수지, 중앙은행 정책 근거로 "왜"와 "다음 방향"의 1차 초안.
2. 원자재 조달 담당자 — 이 변동폭이 수입 원자재(밀가루, 유지, 포장재 등) 원가에 실질적 영향을 줄 수준인지 판단. 하루 몇 원 변동은 대부분 노이즈임을 인지.
3. 재무·헤지 전략가 — 방향성 전망이 실제 대응(선물환·옵션)할 신호인지, 그냥 지켜볼 수준인지 걸러냄.
4. 리스크 관리자 — 너무 낙관적이거나 한쪽으로 쏠린 전망이 아닌지 반대 시나리오 점검.
5. 가격·마진 전략가 — 결국 원가·가격에 어떤 의미인지, 지금 뭔가 해야 할 수준인지로 마무리.
목적은 다섯 문장을 만드는 게 아니라, 한쪽 관점에만 기대지 않은 균형 잡힌 결론을 뽑는 것.

## 4단계 — 카카오톡 메시지 작성 및 발송

통화별로 **따로** 3줄 메시지를 만든다 (총 2통). 각각 전체 200자 이내 (카카오톡 발송 도구 자체가 200자 제한) — 넘으면 "이유" 줄부터 줄인다.

```
💵 [USD/KRW] 변동: [어제/직전 거래일 대비] [▲/▼][N.NN원] ([전일 종가]원 → [오늘]원)
🔍 이유: [당일 주요 재료 1문장]
📈 전망: [단기 방향성 1문장, 확률적 톤] + [짧은 실무 시사점]
```

```
💴 [JPY/KRW·100엔] 변동: [어제/직전 거래일 대비] [▲/▼][N.NN원] ([전일 종가]원 → [오늘]원)
🔍 이유: [당일 주요 재료 1문장]
📈 전망: [단기 방향성 1문장, 확률적 톤] + [짧은 실무 시사점]
```

▲는 상승(원화 약세), ▼는 하락(원화 강세)이다. 방향 표시를 헷갈리지 않는다. `KakaotalkChat-MemoChat` 도구로 USD 메시지, JPY 메시지 순서로 각각 발송한다. 발송 승인을 다시 묻지 않는다 — 이 자동화 자체가 사용자의 사전 승인이다.

## 5단계 — 근거 기사 링크 발송

메시지 총량이 너무 많아지지 않도록, 2-1단계에서 확정한 목록 중 통화당 **최대 2개**만 골라 각각 별도의 카카오톡 메시지로 보낸다 (총 최대 4통 추가). 이유·전망 문장에 실제로 반영된 기사를 우선한다.

각 메시지 형식:

```
🔗 [USD 또는 JPY][매체명] 한 줄 제목
URL
```

- URL은 2단계에서 실제로 확인한 것만 쓴다 — 지어내거나 추측한 링크는 절대 보내지 않는다.
- 제목이 길어서 200자를 넘을 것 같으면 제목을 줄인다 — URL이 잘리면 안 된다.
- 조사한 기사가 통화당 2개가 안 되면 채워지는 만큼만 보내고, 억지로 채우지 않는다.
- 각 발송도 승인을 다시 묻지 않는다.

## 6단계 — 상세 HTML(Artifact) 갱신

카카오톡 요약과 같은 내용을 더 상세하게 볼 수 있는 HTML을 매번 갱신한다. **탭 구조**(💵 달러 USD/KRW, 💴 엔화 JPY/KRW)로 두 통화를 한 페이지에서 전환해서 볼 수 있게 되어 있다. 고정 URL 하나를 계속 덮어써서 "북마크 하나로 매일 최신 내용 보기"가 되게 한다 — 매번 새 아티팩트를 만들지 않는다.

**고정 아티팩트 URL**: `https://claude.ai/artifact/5FPjtyMXbCiRb8f3sDey6D`

절차:
1. `Artifact` 도구를 `action: "read"`, `url: 위 고정 URL`로 호출해 현재 HTML을 읽는다. 이 세션은 이 아티팩트를 발행한 적이 없으므로 반드시 먼저 읽어야 그 위에 발행할 수 있다.
2. 읽어온 HTML의 구조(CSS·탭·레이아웃·톤)는 그대로 두고, 아래를 **USD 탭(`#panelUsd`)과 JPY 탭(`#panelJpy`) 각각에** 오늘 데이터로 교체한다:
   - `#genDate` — 오늘 날짜(요일 포함), "OOOO-OO-OO (요일) 마지막 갱신" 형식 유지
   - `#alertUsd`, `#alertJpy` — 정기 실행에서는 두 배너 모두 `is-shown` 클래스를 **제거**한 상태(숨김)로 둔다. 이 배너는 5% 급변동 알림 작업 전용이다.
   - `.rate-value` (`#rateValueUsd`/`#rateValueJpy`) — 오늘 현재가 (JPY는 100엔 환산값)
   - `.delta-pill` (`#deltaPillUsd`/`#deltaPillJpy`) — 방향 화살표·변동폭·%, 클래스도 `is-up`/`is-down`으로 오늘 방향에 맞게
   - `#rateSubUsd`/`#rateSubJpy` — "전일 종가 X원 → 현재 Y원 · 날짜 시각 기준" 문장
   - 레인지 차트 SVG(통화별로 2개 존재) — 각 통화의 52주 최저/최고로 좌우 라벨과 마커 위치를 계산. 마커 x좌표 = `30 + (오늘값-52주최저)/(52주최고-52주최저)*(570-30)`. 방향에 따라 라인·마커 색을 `var(--up)`/`var(--down)`으로. 마커 아래 텍스트, range-label 하단 문구(52주 내 위치·1년 변동률)도 갱신
   - 각 탭의 "오늘 왜 움직였나" / "다음 며칠 전망" 문단 — 2단계 조사를 바탕으로 2~4문장, 근거 없는 내용 추가 금지
   - `.note` 콜아웃 — 상태 배지(관망/주의/대응 검토 등)와 실무 시사점. 변동폭이 평소보다 크면 `.note`에 `is-warning` 클래스를 추가해 강조색으로 표시(5% 미만이면 이 정도까지, 5% 이상은 알림 작업이 처리)
   - 각 탭의 근거 기사 목록(`.sources`) — 2-1단계에서 확정한 목록 전부(통화당 3~5개, 부족하면 있는 만큼)를 매체명·제목·URL·요약과 함께 넣는다. `.source-item`을 기사 수만큼 반복해서 추가/삭제한다.
   - `<footer>`의 "실제 업무 판단·의사결정과는 관련이 없습니다" 등 안내 문구는 그대로 둔다 (지우거나 고치지 않는다).
3. 수정한 HTML을 `Artifact` 도구로 `action: "publish"`(기본값), `url: 위 고정 URL`, 같은 `file_path`로 다시 발행한다. `favicon`·`title`은 이미 설정돼 있으므로 생략한다.
4. 발행이 끝나면 카카오톡으로 메시지 한 통을 더 보낸다: `🔗 더 자세히 보기(달러·엔화 탭): https://claude.ai/artifact/5FPjtyMXbCiRb8f3sDey6D`
5. `read` 단계에서 버전 충돌 오류가 나면, 새로 받은 최신 버전 위에 같은 방식으로 다시 반영해서 발행한다 — force로 덮어쓰지 않는다.

## 7단계 — GitHub Pages 반영
